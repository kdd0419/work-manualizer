# 001. 실제 회사 데이터 대신 가상 업무 시스템을 사용한다

- 날짜: 2026-11-18
- 상태: 일부 변경됨 → [006](006-실제-업무-사용과-사내-AI.md) (가상 데이터 원칙은 **개발·시험 단계**에 적용. 최종 목표는 실제 업무 사용이며, 실제 업무의 AI는 사내 API로 교체)

## 상황
업무 녹화 매크로 AI는 사용자가 브라우저에서 업무를 시연하는 과정을 녹화하고,
화면 스크린샷과 입력값을 외부 LLM API에 보내 해석한다.
실제 증권사 업무 시스템을 녹화하면 고객 정보, 거래 데이터, 내부 시스템 구조가
녹화 파일과 외부 API 요청에 그대로 담기게 된다.

## 고민한 선택지
1. **실제 사내 시스템을 녹화한다**
   - 장점: 현실적인 결과를 얻을 수 있다.
   - 단점: 개인정보·영업비밀 유출 위험, 사내 보안 규정 위반, 외부 API 전송 불가.
2. **실제 시스템을 녹화하되 민감 정보를 마스킹한다**
   - 장점: 현실성 유지.
   - 단점: 스크린샷 속 정보까지 완벽히 가리기 어렵고, 마스킹 누락 한 번이 사고가 된다.
3. **실제 업무 흐름을 본뜬 가상 업무 시스템을 직접 만든다**
   - 장점: 유출될 실제 정보가 아예 없다. 화면 구조(id, label)를 녹화에 맞게 설계할 수 있고,
     같은 조건으로 반복 평가하기 쉽다.
   - 단점: 실제 시스템보다 단순해서 현실의 복잡함(느린 응답, 팝업 등)을 덜 반영한다.

## 결정
선택지 3. 저장소 안의 가상 증권사 업무 시스템(`mock_system/`)만 녹화 대상으로 쓴다.

## 이유
- 프로젝트의 목적은 "녹화 → 해석 → 매뉴얼/매크로 생성" 방법을 검증하는 것이지,
  특정 실제 시스템을 자동화하는 것이 아니다.
- 실제 데이터가 없으면 외부 LLM API에 스크린샷을 보내도 문제가 없다.
- 회사명, 업체명, 숫자는 모두 지어낸 값이며 시드 스크립트로 언제든 재생성할 수 있다.
- 부가 규칙: API 키는 `.env`에만 두고, `.env`와 `recordings/` 원본은 커밋하지 않는다.
