# 005. 녹화 스크린샷 시점 개선, 매뉴얼 부분 수정, 업무 연결

- 날짜: 2026-11-26
- 상태: 결정

## 1. 사이트 이동 시 녹화 화면이 멈추는 문제

### 증상
네이버 → 다른 사이트처럼 사이트를 옮기며 녹화하면, 매뉴얼에 단계는 남지만 스크린샷이 빈 화면이거나 앞 화면과 같거나,
고정 메뉴가 그림 중간에 끼어 있었다. 녹화 중 브라우저가 잠깐씩 멈춘 것처럼 보였다.

### 원인 (실험으로 확인)
1. Playwright의 `page.screenshot`은 **웹 글꼴이 다 내려받아질 때까지 기다린다**. 글꼴이 많은 외부 사이트에서는 첫 캡처에 8초 이상.
   그동안 녹화기가 다음 동작을 처리하지 못했다.
2. 페이지 전체(위~아래)를 찍어 긴 페이지는 느리고, 스크롤하며 이어 붙이는 과정에서 고정 메뉴가 중간에 찍혔다.
3. 이벤트 처리 함수 안에서 "로딩 완료"를 기다리면, 그 완료 신호를 처리할 차례가 오지 않아 **서로 기다리다 멈췄다**.
4. 클릭 순간에 찍으면 이미 페이지 이동이 시작돼 캡처가 멈추거나 다음 화면이 찍혔다.
5. 처리 순서상 "로딩 완료" 신호가 "페이지 이동" 기록보다 먼저 오는 경우가 있었다.

### 결정
- 브라우저 자체 캡처(CDP `Page.captureScreenshot`)로 **보이는 화면만** 찍는다 (글꼴을 기다리지 않음, 0.03~0.05초).
- 클릭: **누르는 순간(pointerdown)**, Enter 제출: 키를 누르는 순간 미리 찍어 둔다.
- 페이지 이동: 로딩이 끝나고 **0.35초 뒤**, 녹화기 바깥 반복(flush)에서 찍는다. 사용자가 그 전에 동작하면 그때 바로 찍는다.
- 캡처에 실패한 입력 단계는 같은 페이지의 바로 앞 화면을 쓴다.
- 누른 요소 위치에 빨간 상자를 그린다 (매뉴얼에서 어디를 눌렀는지 보이게).
- 자동 시연(평가) 스크립트의 클릭은 사람처럼 페이지 안에서 일으킨다 (`_HumanPage`).

### 확인
가상 포털 → 다른 주소(127.0.0.1)로 이동 → 새 탭까지 녹화를 4회 반복: 모든 화면이 맞게 찍힘.

## 2. 조사 표기 '을(를)'

규칙 기반 문장은 앞말 받침을 몰라 `을(를)`로 적었다. API(AI)를 켜면 AI가 쓴 설명은 자연스럽지만,
규칙 기반 값(질문, 변수 설명, AI 실패 시 설명 등)은 그대로 남으므로 AI만으로는 해결되지 않는다.
→ `analyzer/josa.py`: 앞 글자 받침(한글·숫자·영어 끝 글자, 괄호 설명은 건너뜀)을 보고 하나로 고친다.
만들 때와 화면에 보여 줄 때 모두 적용해, 예전에 만든 매뉴얼도 화면·다운로드에서는 자연스럽게 보인다.

## 3. 매뉴얼 부분 수정
- 매뉴얼을 제목 / 섹션 / '처리 순서'의 단계 하나하나로 나눠, 그 부분만 마크다운으로 고친다. 전체 편집도 가능.
- 저장·다시 생성 전에 이전 내용을 `recordings/<id>/manual_history/`에 보관(최대 20개), **↶ 이전 버전**으로 되돌린다.
- 직접 고친 뒤 다시 생성하려 하면 먼저 확인을 받는다.

## 4. 업무 연결 (A 결과 → B 입력)
- 연결 정의 `chains/<id>.json`, 실행기 `runner/chain.py`. A의 결과 파일(웹 다운로드, 엑셀 `_결과.xlsx`)을 B의 파일 변수에 넣는다.
- 두 번째 업무부터는 파일 변수가 있는 매크로(엑셀)만. 중간 실패 시 멈춤.
- 단계별 변수 값(비밀번호 포함)은 명령줄이 아니라 임시 파일로 넘기고 실행기가 읽자마자 지운다.
- 단일 실행 결과에서도 "이 결과로 다음 업무 실행 준비", "이 파일로 Excel 녹화"를 바로 할 수 있다.
- 확인: 증권사 점검 현황 CSV 다운로드(웹) → 그 CSV에서 '적합' 행 삭제·정렬·합계(엑셀) 연결이 한 번에 성공.
