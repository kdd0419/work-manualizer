# eval/ — 버전별 성능 평가

## 재실행 성공률

| 버전 | 방식 |
|---|---|
| v1 | 녹화 그대로 재생. 입력값을 바꿀 수 없음 (기준선) |
| v3 | 변수 매크로. 실패 감지 없음 |
| v4 | 변수 매크로 + 실패 감지(0건, 오류, 다른 페이지) |

### 순서

가장 간단한 방법: 관리 화면 **⑤ 평가 결과 → 평가 실행** 버튼, 또는 `python -m eval.run_all [--no-ai]`.
(데이터 초기화 → 녹화 → 매크로 생성 → 평가 → 오늘 기준 데이터로 복원까지 한 번에)

단계별로 직접 할 때:

```powershell
# 0) 데이터 초기화 (가상 업무 시스템 서버를 끈 상태에서) 후 서버 다시 켜기
python -m mock_system.seed --base-date 2026-11-18
python -m mock_system.app

# 1) 시나리오 10개를 자동으로 시연·녹화 → eval/recordings_index.json
python -m eval.record_scenarios            # --show 를 붙이면 브라우저 창이 보임

# 2) 시나리오마다 해석 + 변수 인식 + 매크로 생성
python -m eval.build_macros                # Gemini 사용 (시나리오당 요청 2~3번)
python -m eval.build_macros --no-ai        # 규칙 기반 (키 없이)

# 3) 평가 실행 → docs/results/<날짜>_<버전>.md (+ .json)
python -m eval.replay_eval --version v1 v3 v4
```

무료 한도에 걸리면 `--only S01 S02 …`로 나눠 실행하세요.

### 시나리오 (`scenarios.json`)

- 업무 10개 × 입력값 3세트 = 버전당 30회 실행
- 세트 1은 녹화 때와 같은 값, 세트 2·3은 다른 값입니다. v1은 값을 바꿀 수 없어 세트 2·3에서 실패하는 것이 정상입니다.
- `inputs`의 키는 요소 id 또는 name입니다. 매크로에서 그 요소를 쓰는 변수에 값을 넣습니다.
  AI가 그 값을 변수로 인식하지 못했으면 보고서 비고에 "변수로 인식 안 됨"이 남습니다.
- 성공 판정
  - `download`: 마지막 단계까지 완료 + 해당 파일명이 모두 다운로드됨
  - `message`: 마지막 단계까지 완료 + 화면 메시지(저장 완료)에 문구가 포함됨
  - `stop`: 그 원인으로 멈춰야 성공 (예: 결과 0건을 알아차리고 멈췄는지)

### 참고: 규칙 기반(AI 없이) 결과 — 2026-11-18

| 버전 | 성공 | 비고 |
|---|---|---|
| v1 | 10/30 | 세트 1만 성공 (입력값 변경 불가) |
| v3 | 28/30 | 결과 0건 2개를 알아차리지 못하고 다음 단계에서 실패 |
| v4 | 30/30 | 결과 0건에서 정확히 멈춤 |

이 시나리오는 모든 입력칸이 id·label을 갖춘 단순한 화면이라 규칙 기반으로도 잘 됩니다.
AI 버전에서는 **변수 인식이 맞았는지**(날짜 규칙, 고정/변수 구분)와 **매뉴얼 품질**을 함께 비교하세요.
