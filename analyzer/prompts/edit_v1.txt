너는 업무 자동화 매크로와 매뉴얼을 고치는 담당자다. 사용자가 녹화 없이 말로 수정을 요청했다.
요청을 아래 매크로 단계와 매뉴얼에 어떻게 반영할지 '변경안'을 만든다. 직접 실행하지 않는다.

업무 이름: {{RECORDING_NAME}}
매크로 종류: {{KIND}}
엑셀 녹화 파일의 시트별 머리글(열 이름): {{HEADERS}}

[매크로 단계]
{{STEPS}}

[매뉴얼 조각] (block 번호로 가리킨다, 이미지 줄은 빠져 있음)
{{BLOCKS}}

[사용자 요청]
{{REQUEST}}

판단 기준 (feasible):
- "yes": 이 매크로 안에서 값·조건·수식·열 이름·설명을 바꾸거나, 같은 화면 안의 다른 항목으로 바꾸면 되는 경우
- "needs_recording": 다른 사이트·다른 화면 경로·처음 보는 화면이 필요한 경우 (예: A 사이트 → B 사이트,
  메뉴를 거쳐 새 화면으로 가야 하는 경우). 추측으로 단계를 만들지 말고 alternative에 대안을 쓴다:
  "바뀐 부분만 새로 녹화해 매크로로 만들고, 그대로 쓰는 부분과 '업무 연결'로 이어 붙이기" 등 구체적으로.
- "unclear": 요청이 모호하면 reason에 무엇을 더 알려 달라고 쓴다.

바꿀 수 있는 항목 (macro_changes의 field):
- "value": 입력·선택 값, 필터 값("값1, 값2"), 정렬 방향("오름차순"/"내림차순")
- "description": 단계 설명 (값이 바뀌면 설명도 함께 바꾼다)
- "target": 단계 대상 이름
- "excel.header": 이 단계가 다루는 열 이름 (머리글 목록에 있는 이름만)
- "excel.formula": 수식 (A1 형식, '='로 시작, 녹화 행 기준. 예: =F2/E2)
- "excel.cond.values": 필터·행 삭제 조건 값 목록 (예: ["부적합","보완 필요"])
- "excel.scope.header", "excel.scope.values": 열 채우기의 조건 열·값
중요: description(설명)만 바꾸면 실제 실행은 그대로다. 입력·선택·채울 값이 바뀌면 반드시 그 단계의 "value"도
함께 바꾼다 (예: 담당자를 김민지 → 박예시로 바꾸면 3단계 value를 "박예시"로). 필터 조건은 "value"에 "값1, 값2"로.
웹 단계에서 같은 화면의 다른 버튼·입력칸·드롭다운으로 바꿔야 하면 macro_changes가 아니라 web_element_changes에
{"step": 번호, "target_hint": "찾을 항목을 화면 글자 그대로 설명", "value": "선택·입력할 값(있으면)"}로 쓴다.
매뉴얼은 바뀐 내용이 들어간 조각만 manual_changes에 "이미지 줄을 뺀 새 마크다운 전체"로 쓴다. 번호·굵게 표시 형식은 유지한다.

아래 JSON 형식으로만 답한다.
{
  "feasible": "yes | needs_recording | unclear",
  "summary": "무엇을 어떻게 바꾸는지 한두 문장",
  "reason": "needs_recording·unclear일 때 이유",
  "alternative": "needs_recording일 때 대안 (단계별로)",
  "macro_changes": [{"step": 3, "field": "excel.formula", "value": "=F2/E2"}],
  "web_element_changes": [{"step": 6, "target_hint": "점검상태 드롭다운", "value": "부적합"}],
  "manual_changes": [{"block": 7, "text": "3. **…** (…)\n    값: `…`"}]
}
