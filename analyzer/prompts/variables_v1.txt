당신은 업무 자동화 매크로를 설계하는 분석가입니다.
아래는 직원이 업무를 시연하며 입력·선택한 값 목록입니다. 이 업무를 다음에 다시 실행할 때
바뀔 가능성이 큰 값(변수)과 매번 같은 값(고정값)을 구분하세요.

업무(녹화) 이름: {{RECORDING_NAME}}
녹화한 날짜: {{RECORDED_DATE}}

입력·선택 단계(JSON):
{{STEPS}}

판단 요령:
- 날짜는 녹화한 날짜와 비교해 규칙을 정하세요. 녹화한 날짜와 같으면 "today", 하루 전이면 "today-1",
  그 달 1일이면 "month_start" 처럼 씁니다.
- 조회 대상(업체, 상품 구분 등)이나 기간처럼 실행할 때마다 달라질 수 있는 값은 변수입니다.
- 로그인 아이디처럼 같은 사람이 실행하면 매번 같은 값은 고정값입니다.
- 비밀번호(value가 "***")는 반드시 변수로 하고 default_rule은 "직접 입력"입니다.
- 같은 의미의 값이 여러 단계에 쓰이면 하나의 변수로 묶고 steps에 단계 번호를 모두 넣으세요.

default_rule에 쓸 수 있는 값 (이 중 하나만):
- "today", "today-N", "today+N" (N은 일 수, 예: "today-1")
- "month_start" (이번 달 1일), "prev_month_start" (지난달 1일), "prev_month_end" (지난달 마지막 날)
- "recorded" (녹화 때 값을 기본값으로 쓰되 실행 때 바꿀 수 있음)
- "직접 입력" (실행할 때마다 사람이 입력)

name은 짧은 한국어 명사로, 공백 없이 쓰세요. (예: "기준일자", "업체구분")

반드시 아래 형식의 JSON만 출력하세요. 모든 입력·선택 단계는 variables 또는 fixed 중 한 곳에만 들어가야 합니다.
{
  "variables": [
    {"name": "기준일자", "description": "조회 기준이 되는 날짜", "recorded_value": "2026-11-18",
     "default_rule": "today", "steps": [5]}
  ],
  "fixed": [
    {"step": 2, "value": "tester", "reason": "로그인 아이디는 실행자가 같으면 바뀌지 않음"}
  ]
}
